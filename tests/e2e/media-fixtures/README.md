# Offline synthetic audio fixtures

These six-second silent files were generated locally for the browser regression.
They contain no podcast, downloaded media, recorded voice, microphone input, or
other user content. Generation connects a zero-filled Web Audio buffer only to a
virtual `MediaStreamDestination`; it never connects to the speaker destination.

- `silence.mp3`: MPEG Layer III, 44100 Hz mono, generated by local Python
  `soundfile` 0.14.0 / libsndfile from a zero-filled NumPy array.
- `silence.m4a`: AAC LC, 44100 Hz stereo, in fragmented MP4, encoded by an already
  installed Chromium `MediaRecorder` from the silent virtual stream.
- `silence.aac`: the same encoded AAC packets, extracted according to the MP4
  `trun` sample-size tables and wrapped in ADTS. The generator validates the MP4
  channel count, sample rate, AudioSpecificConfig and aggregate sample sizes.

The optional offline generator is `../generate_media.py`. It requires preexisting
Python `soundfile`, NumPy, Playwright and an installed Chromium with AAC encoding:

```text
CHROMIUM_PATH=<existing Chromium executable> python tests/e2e/generate_media.py
```

Regeneration is unnecessary during tests and may produce different binary output
with different encoder versions. `tests/e2e/media.py` uses the checked-in files,
the production-compiled `frontend/dist/player.js`, and an isolated server bound
to an OS-selected loopback port. It runs Chromium headlessly with muted audio.
No new encoder dependency, desktop window, real account or external media service
is needed at test time.

The tests check actual decoding, HTTP Range and complete-body responses, seeking
and progress behavior. These short synthetic Chromium results do not establish
Windows WebView2 behavior, system device/media-key behavior, support for every
file using these formats, real CDN behavior, or long-session reliability.
