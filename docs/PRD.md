# 小宇宙非官方桌面客户端
## 产品需求文档 PRD · v0.1

**研究日期：2026-09-12｜目标平台：Windows 11 x64｜状态：调研完成，接入与实机验证待执行**

产品定位：把用户在手机小宇宙中已经订阅、收藏的内容，带到 Windows 上方便、连续地收听。

本文件是产品与研发评审稿，不是已实现功能清单。功能指标均为拟定验收要求；社区项目的功能声明，不等同于本项目已完成真实账号验证。独立品牌名尚未确定，本文名称仅描述兼容对象，不暗示官方关系。

**建议决策：有条件立项。先验证账号接入闭环及平台使用边界，再开发完整桌面产品；不要把“网页套壳”当作登录和云端收藏问题的解决方案。**

交付范围：现状调研、竞品与技术路线、MVP 功能、交互规则、数据与安全边界、测试验收、里程碑及开源策略。未包含应用源代码或可安装程序。

## 1. 执行摘要与产品目标

### 1.1 用户需求的准确表达

用户希望有一个开源的 Windows 小宇宙桌面客户端，最好能登录自己的账号，查看已经收藏的播客并播放。本文将“收藏的播客”拆为两个独立对象：**订阅的节目**和**收藏的单集**；两者均纳入目标版 MVP，不以本地新建书签替代既有云端数据。

主要使用情境是假设中的工作、学习及居家电脑收听：用户在手机上发现内容，在电脑上选择并持续播放，不需要完整复制移动端社区。该情境尚未经过用户访谈验证。

### 1.2 立项结论

**技术上值得验证，但不能直接承诺账号功能长期可用。**公开页面提供单集信息；社区已有桌面客户端和账号相关接口实现。Horizon 声明支持 Windows/macOS，并在 2026 年 5 月的 v0.6.0 版本声明修复登录问题，同时保留第三方登录风控或封禁警告。[S02][S04][S05][S06]

本次未发现面向第三方听众客户端的官方公开 API/OAuth 文档。此结论仅代表本次公开检索范围，不排除合作接口或未公开授权方案。官方首页及主播后台入口也不能证明存在完整的听众个人库网页版。[S01][S03]

### 1.3 三个独立门槛

| 门槛 | 必须取得的证据 | 未通过时的决策 |
| --- | --- | --- |
| G1 接入与发布边界 | 明确账号接入、内容使用和公开分发的许可依据；存在争议时取得专业法律评估，必要时取得平台许可 | 不公开承诺或分发有争议的账号接入能力 |
| G2 账号完整闭环 | 登录、身份核对、令牌续期、订阅完整分页、收藏单集完整分页、正常退出的实测记录 | 暂停“账号版 MVP”验收；不得拿本地书签冒充云端收藏 |
| G3 Windows 播放闭环 | 真实音频播放、拖动进度、后台播放、媒体键、异常恢复、安装与卸载验证 | 先修复桌面基础；必要时调整宿主框架 |

技术验证与发布许可不是同一件事，测试成功不能代替 G1。默认路线是独立界面、只读个人库、凭据仅保存在本机、可替换的平台适配层。

### 1.4 成功的定义

核心任务是“用户打开桌面客户端，从自己的小宇宙收藏单集中选择一集并开始播放”；再次启动能继续本机上次的进度。连接失败时要能清楚解释原因，不能假装空收藏，也不能反复触发登录请求。

## 3. 产品与技术路线选择

### 3.1 三条产品路线

| 路线 | 优点 | 主要限制与取舍 |
| --- | --- | --- |
| A. 官方网页套壳 | 初始界面工作少，保留网页体验 | 不能凭空补齐听众登录、个人库和跨页面播放器；不作为目标方案 |
| B. 独立桌面界面 + 平台适配层 | 能围绕个人库、持续播放和系统操作设计；平台变化与 UI 隔离 | 需要维护接入与安全边界；推荐作为账号版目标路线 |
| C. 通用 RSS/公开链接播放器 | 可独立提供本地书签、队列、进度，减少账号依赖 | 无法自然还原小宇宙云端收藏；只能作为明确降级后的另一产品范围 |

先评估现有 Horizon 是否已覆盖核心需求。能通过安全、许可与体验检查时，贡献或 fork 更经济；独立重写仅在需要明显不同的架构、安全模型或许可证策略时成立。

### 3.2 推荐基线与替代条件

**研发基线建议：Wails 2 + Go + React/TypeScript + SQLite，Windows 11 x64 优先。**Wails 使用系统 WebView，Windows 依赖 WebView2；Horizon 也采用这一路线，但其存在并不替代本项目验收。[S04][S10][S11]

选择理由是业务接口和本地状态可收敛在 Go 层，前端负责列表与音频交互；这是本次方案建议，不是对团队现有语言偏好的假定。依赖具体版本在 M0 通过后锁定，禁止构建时浮动到 latest。

| 宿主 | 适用判断 | 切换/选择条件 |
| --- | --- | --- |
| Wails 2 | 本方案优先试验，业务服务 Go 化 | 必须证明托盘、媒体键、隐藏窗口播放和 WebView2 分发可用 |
| Electron | 备选，已有官方托盘与安全存储相关能力 [S12][S13][S14] | 团队以 TypeScript 为主，或 Wails 的原生集成成本过高时选择；接受随应用维护浏览器运行时 |
| Tauri 2 | 可选，重视能力授权隔离且具备 Rust 维护能力 [S15] | 无需为追求“小安装包”单独引入团队不熟悉的栈 |

HTML 音频和 Media Session API 是实现手段，不是“Windows 系统媒体控制已支持”的验收证据。尤其不能把浏览器文档中的能力自动等同于所有嵌入式 WebView 的行为。[S17]

### 3.3 不采用的捷径

不以关闭跨域/浏览器安全、通用代理任意网址、读取其他应用的会话存储、绕过验证码或设备风控来换取功能。社区代码的技术可行性、开源许可与平台允许第三方接入的范围，分别评审。

## 4. MVP 范围与术语

### 4.1 数据术语

| 名称 | 含义 | 首版来源与修改范围 |
| --- | --- | --- |
| 订阅节目 | 用户在小宇宙关注的节目，可包含多期单集 | 从账号读取；不在桌面端更改订阅关系 |
| 收藏单集 | 用户在小宇宙收藏的某一期节目内容 | 从账号读取；不在桌面端增删云端收藏 |
| 本地书签 | 用户只在本桌面应用保存的节目或单集链接 | 本机增删，始终标记“仅此设备” |
| 稍后听队列 | 本机计划播放的单集顺序 | 本机增删、置于下一集、清空 |
| 收听进度 | 本桌面端记忆的单集位置 | 首版仅本地保存，不声称手机进度同步 |

### 4.2 优先级

| 优先级 | 交付内容 |
| --- | --- |
| P0 账号版核心 | 单账号登录/续期/退出；订阅列表；收藏单集列表；完整分页；节目详情与单集列表；当前同步状态 |
| P0 播放与桌面 | 播放/暂停/拖动/倍速/音量；队列；本机续播；后台播放；托盘操作；媒体播放暂停键；公开链接打开 |
| P0 安全与交付 | 系统凭据保护；内容清洗；只读云端；数据清除；诊断日志脱敏；Windows 安装/卸载；构建和开源文档 |
| P1 | 明确授权后的收藏/订阅写回；库内完整搜索；迷你播放器；主题；自定义快捷键；受控的更新提示 |
| P2 或另立项 | 云端进度同步；多账号；macOS/Linux；RSS/OPML；允许情况下的离线收听 |

首版不做推荐算法、评论互动、付费内容解锁、全站爬取、批量下载、媒体转存、AI 转写或总结、自建云端账号代理、手机完整功能复制。

### 4.3 账号失败时的范围约束

允许保留“公开链接 + 本地书签 + 播放”访客模式，但必须明示其不包含小宇宙账号收藏。**G2 未通过时，账号版 MVP 判为未完成。**不能把登录按钮隐藏后仍宣传已完成用户的原始目标。

平台范围默认只承诺 Windows 11 x64；其他 Windows 版本、ARM64 和其他操作系统需要独立测试，不能依据框架支持范围直接宣称产品支持。

## 5. 信息架构与关键用户流程

### 5.1 主窗口结构

左侧导航为“继续收听、我的订阅、收藏单集、本地书签、稍后听、设置”；顶部为页面标题、局部筛选、刷新及账号状态；中间展示列表或详情；底部常驻播放器。任何页面切换不得重新创建正在播放的音频实例。

首次打开提供“连接小宇宙账号”和“先使用公开链接”两条入口。未登录访问个人库时，显示明确的登录引导，不使用“暂无收藏”代替未登录状态。

列表卡片展示封面、节目或单集名、所属节目、时长/发布时间、是否已在本机听过；缺失字段不伪造。节目详情展示简介和可分页单集列表；单集详情展示清洗后的 Show Notes 及可识别的时间点。

### 5.2 关键任务

| 场景 | 用户流程 | 完成状态 |
| --- | --- | --- |
| 首次听收藏 | 打开应用 → 连接账号 → 核对昵称 → 收藏单集 → 点击播放 | 当前单集与底部播放器一致，音频可听 |
| 听已订阅节目 | 我的订阅 → 选择节目 → 查看单集 → 播放或加入稍后听 | 订阅关系不被改变，队列可见 |
| 继续上次收听 | 再次启动 → 继续收听 → 用户点击继续 | 从本机保存位置续播，启动时不自动外放 |
| 离开电脑窗口 | 播放中关闭主窗口 → 用户选择最小化到托盘 | 音频持续，托盘可暂停/显示/退出 |
| 打开分享链接 | 用户主动粘贴文本 → 识别合法节目/单集链接 → 打开详情 | 不后台监听剪贴板，不执行分享文本中的其他内容 |

### 5.3 统一状态表达

每个列表必须区分加载中、正常数据、真实空列表、加载失败、缓存过期、部分已加载、功能不可用和未登录。同步状态至少包含最后成功时间和范围，例如“已加载 40 条，还有更多”，而不是含糊的“同步成功”。

只有收到明确的结束标志并完成必要的完整性校验，才显示“本轮已全部加载”。若上游不提供快照一致性，不承诺在并发变更期间获得某个瞬间的严格全量视图。

### 5.4 交互约定

点击“播放”只替换当前播放项，并从待播队列移除同一单集，保留其余队列；“下一集播放”将目标移动到队首，不插入重复项；自然播放结束才自动前往下一集。键盘焦点位于输入框时，空格不能被播放器劫持。媒体键和普通页面快捷键采用不同的事件路径并做去重。

## 6. 账号与会话需求

### FR-01 登录接入与状态

P0。M0 必须选定至少一种经验证且许可边界清楚的登录方式，并形成接入记录。优先使用平台实际允许的授权流程；本次没有找到可直接承诺的听众 OAuth/扫码能力。社区短信登录只能作为待核验路线，不能因为 README 存在就默认开启。[S03][S05][S06]

如采用经核验的短信方式，必须由用户主动请求验证码，显示服务端限制和错误；不得后台重发、绕过验证码、规避设备风控或要求用户关闭安全保护。验证码仅短暂保存在内存中。手机号仅用于必要的认证，不进入分析日志。

登录成功后先读取并核对稳定用户 ID 和展示昵称，再关联个人库。UI 显示“已连接”仅表示当前身份已验证，不表示所有列表已全量同步。禁止将示例账号或合成数据展示成当前用户真实收藏。

### FR-02 续期与错误隔离

凭据只在受信任的本地服务层使用，不返回通用前端状态树。令牌刷新采用单飞机制：多个请求同时过期时，只进行一次刷新；成功后每个原请求最多重放一次。刷新后仍未授权，进入需要重新登录状态。

网络超时、DNS 失败或临时服务故障不能直接清空凭据。对于 403，先区分内容权限、账号限制和接口不支持；对于 429，尊重 Retry-After 或已验证的服务端限制。明确风控状态下停止账号请求并提示使用官方客户端核查，不进行自动规避。

令牌有效期、设备标识、刷新返回字段和登录并发限制以验证结果为准，不在 PRD 中臆造常量。刷新令牌发生轮换时必须原子保存；旧请求不得覆盖新会话。

### FR-03 安全存储与退出

Windows 采用用户级 DPAPI 或经评审的系统凭据存储。DPAPI 的用户/机器绑定是保护机制，不代表可防御同一用户权限下的所有恶意进程；不得使用允许同机其他用户解密的机器级选项。[S16]

用户选择退出后，立即停播、取消账号请求、清除凭据与该账号的列表、队列和收听记录，并移除关联缓存。独立访客书签可保留，但不得自动从账号收藏复制。迟到响应通过会话代次校验丢弃。缺少上游注销接口时明确说明这是本地退出，不宣称已撤销平台端令牌。

### 账号验收

正常登录能展示正确昵称与 UID 对应的数据；错误验证码不建立会话；并发过期仅刷新一次；刷新失败不无限循环；断网不误删有效会话；退出后搜索本机持久化数据与日志无令牌残留，账号数据不被下一次登录的其他用户读取。

## 7. 个人库、分页与链接需求

### FR-04 我的订阅

P0。按账号读取已订阅节目，默认遵循上游顺序；没有可信更新时间字段时，不伪装“最近更新”排序。点击节目进入详情及单集列表。首版只读，不暗中提交订阅、取消订阅或星标操作。

### FR-05 收藏单集

P0。展示当前账号在小宇宙收藏的单集，包括所属节目和可播放状态。收藏时间缺失时不虚构；下架或受限单集仍保留可解释的条目和状态，不因无法播放而静默消失。支持局部标题筛选，明确标注“在已加载内容中筛选”。

### FR-06 分页与同步完整性

所有列表采用适配层返回的不透明游标，不能把社区文档未列分页参数解释为没有分页。包装服务的路径和返回格式也不能直接当作官方协议。[S07][S09]

按稳定节目/单集 ID 去重；同一游标反复出现、返回空页但仍带下一游标、结构缺失、页数安全阈值触发时，显示异常或部分结果，不伪装完整列表。正常分页优先用户滚动触发；“加载全部”须由用户主动操作并可取消。

首次进入或手动刷新时拉取首屏；本地缓存未超过建议的 10 分钟时优先展示缓存。自动刷新仅在用户进入相应页面时按过期策略触发，不在后台轮询全部个人库。手动刷新做合并与防连点；请求频率最终以服务端限制为上限，而不是以固定速率强行访问。

一次同步按代次写入暂存视图。中途失败保留上次完整结果，不基于部分分页删除本地条目。上游无稳定快照时显示“本轮加载结束”与校验时间，明确可能受手机侧同期变更影响。

### FR-07 公开链接与详情

P0。支持经核实的官方节目/单集 URL；从分享文本提取链接，校验 HTTPS、精确域名和路径。不支持的短链提示用户提供展开后的正式链接；新增短链域名须经验证后加入允许范围，不能跟随任意网址跳转。

播放解析仅处理用户主动打开或个人库选中的内容，不进行全站遍历。详情可在默认浏览器中打开官方原页。Show Notes 时间点仅在能确定有效时间且媒体支持定位时跳转，其他外链以安全方式交给系统浏览器。

### 个人库验收

用合成数据测试 0、1、50、500 条及异常分页；用经许可的真实账号样本验证至少两页，并核对手机端/平台端参考结果。集合在验证期间保持不变时应无漏项、无重复。公开接口限制导致无法读全时，G2 不通过，而不是仅验证第一页后宣布完成。

## 8. 播放器、队列与进度需求

### FR-08 基础播放

P0。支持播放/暂停、拖动进度、后退 15 秒、前进 30 秒、0.75/1/1.25/1.5/2 倍速、音量调整。音量和倍速保存在本机；拖动范围以实际媒体时长与可 seek 能力为准。无法定位的内容须禁用相应操作并解释，不能显示拖动成功但实际回到原位。

播放器状态为“待机、解析中、缓冲中、播放中、已暂停、已结束、出错”。唯一播放实例独立于页面路由。快速切换时用播放代次取消旧解析结果；当前标题、封面和音频必须来自同一单集，禁止旧请求覆盖新选择。

权限不足或付费受限显示原因与官方打开入口；没有可播放授权时不尝试替代地址获取完整内容。MVP 不提供离线下载按钮，也不主动持久化完整音频；正常播放所需缓冲需在隐私说明中解释。

### FR-09 链接、鉴权与重试

媒体地址可能失效，播放前按需要重新解析；地址失效最多重新解析一次。只对可恢复网络错误做有限退避重试，默认一次操作最多 3 次；暂停、切歌或退出立即取消重试。鉴权失败转入账号流程，不能连续重新登录。

HTML audio 标签不能被假定为可以任意设置认证请求头。M0 分别验证直接媒体 URL、重定向、Range/206、拖动、格式/编解码兼容和地址续期。需要受保护媒体访问时再评估有限的本机转发，不默认启动开放代理，也不把平台令牌拼入播放 URL。[S17]

### FR-10 稍后听与恢复

队列按顺序播放，提供加入末尾、下一集播放、移除和清空。重复加入以同一单集 ID 合并。手动播放只替换当前项并从待播队列移除同一单集；清空队列不打断当前项。当前单集结束后播放下一项；下一项不可用时停止并等待用户处理，不无限跳过。

应用重启恢复队列和最后单集，但默认暂停。会话退出清除该账号队列；访客队列与账号队列严格隔离，不自动迁移。

### FR-11 本机续播

播放期间每 5 秒及暂停、切歌、正常退出时保存位置；正常持久化后的恢复误差目标不超过 5 秒。强制掉电以最后成功提交为准，不承诺零丢失。由实际结束事件标记“本机已听完”，保留重听入口；不修改平台端已听状态。

进度以 provider + accountScope + episodeId 标识，不以会过期的音频 URL 标识。首版不读取或写回手机端播放进度，因此不能宣传跨设备无缝续播。

## 9. Windows 集成、设置与交付

### FR-12 后台与系统控制

P0。最小化或隐藏主窗口不暂停正在播放的音频。首次关闭窗口时询问“最小化到托盘”或“退出”，允许记住选择；托盘至少提供显示窗口、播放/暂停和退出。真正退出必须停止音频并释放进程。

系统媒体播放/暂停键纳入 P0，元数据展示和 Windows 媒体面板集成在 M0 实测；同一次按键不能经多个处理链路执行两次。若系统媒体键因技术限制不能可靠交付，应在评审中明确调整范围，不能悄悄以仅前台空格键代替。

锁屏场景与系统睡眠场景分别验证。系统进入睡眠不承诺继续播放；唤醒后保留位置并默认暂停，待用户确认继续，避免意外外放。音频设备拔出或切换行为必须在实机验证，出现不可控外放风险时优先暂停。

### FR-13 设置与数据控制

P0。提供账号状态、退出、音量/倍速记忆、关闭窗口行为、最后同步时间、缓存清除、重置全部本地数据、诊断导出和版本信息。默认不开机自启、不自动收集使用分析、不建立项目方云端账号。

“清除缓存”不等于退出；“退出账号”不等于删除平台账号；“重置全部本地数据”需二次确认并清除应用自有凭据、库数据、队列与设置。清除操作范围应列明；对数据库及 WebView 缓存做实际清理验证，不承诺取证级安全擦除。

### FR-14 安装与更新

P0 提供 Windows 11 x64 安装包或便携包，并明确 WebView2 运行时依赖。安装过程检测依赖缺失，给出受信任的获取方式；不能把只包含引导安装器的包称为“完整离线包”。便携应用依赖系统运行时也必须说明。[S11]

普通用户权限运行，不要求管理员权限来绕过限制；升级应保留有效设置并验证数据迁移，迁移失败不得覆盖原数据。卸载明确询问是否删除用户数据，保留数据选项不会把令牌导出到可共享目录。

首版使用人工确认的发布包更新，不实现远程下载脚本并执行。发布包附源码版本、校验值、依赖清单和签名状态；校验值不是发布者身份认证的替代。公开分发前评估代码签名和系统信誉提示，不能宣称签名后绝无安全提示。

### FR-15 可用性

首版提供简体中文。键盘可完成核心任务；控件有可读名称与可见焦点。验证 100%、150%、200% DPI，窗口缩小时播放器和错误提示不能互相遮挡。较长标题截断后可查看全文；列表大量数据采用分页和虚拟化，不能卡住音频控制。

## 10. 系统边界与数据模型

### 10.1 逻辑分层

本地界面负责展示、交互与持久的播放控制器；桌面桥接层提供受限业务方法；Go 服务层负责认证、请求调度、数据规范化和本地存储；平台适配层负责与具体上游协议交互；系统集成层负责凭据、托盘和媒体键。

默认没有项目方服务器，用户凭据不经过第三方公共代理。元数据请求从本机发往经评审的平台服务，音频从合法来源播放。上游返回网页、Show Notes、图片和 URL 均视为不可信输入，不能获得本机文件或命令执行权限。[S12][S15]

### 10.2 内部业务接口（不是官方 API）

| 接口域 | 需要表达的业务能力 |
| --- | --- |
| AccountProvider | 登录方式能力、连接、当前身份、刷新、退出本机会话 |
| LibraryProvider | 订阅列表、收藏单集列表、节目详情、节目单集分页、单集详情 |
| PlaybackResolver | 在当前权限下解析播放资源、是否支持 seek、资源失效重新解析 |
| LocalStateStore | 本地书签、队列、进度、页面缓存、设置及同步状态 |
| DesktopBridge | 托盘、媒体键、窗口、系统凭据、安全打开外部链接 |

能力状态以明确枚举表达，如可用、未验证、暂时不可用、不支持。未验证能力默认不在正式版开放。将来某个接口失效时应能单独关闭，不连带禁用已验证的访客播放能力。

### 10.3 最小数据模型

| 实体 | 关键字段与约束 |
| --- | --- |
| AccountScope | provider、稳定 userId、本机会话代次；访客使用独立 scope |
| Podcast / Episode | providerId、标题、节目关联、公开来源链接、必要展示字段 |
| Subscription / CloudFavorite | accountScope、对象 ID、同步代次、获取时间；云端只读 |
| LocalBookmark / QueueItem | scope、对象 ID、本地顺序或保存时间；不冒充云端关系 |
| PlaybackProgress | scope、episodeId、position、duration、ended、updatedAt |
| SyncState | 列表类型、cursor、generation、部分/完整/失败状态、最后成功时间 |

SQLite 存储元数据及本地状态，凭据单独进入系统保护存储。临时音频地址不作为长期主键，带签名的地址不进入普通日志。元数据默认并非加密保险箱，需告知用户本地文件权限边界。

## 11. 安全、隐私与平台边界

### 11.1 安全基线

| 风险 | P0 要求 |
| --- | --- |
| 凭据泄漏 | 用户级系统保护存储；前端无原始 token；日志、诊断、异常堆栈和发布包无敏感头/验证码 |
| Show Notes 注入 | HTML 允许列表清洗；禁用脚本、事件处理器及危险 URL 协议；时间点链接按自有规则解析 |
| 桌面桥接滥用 | 仅加载本地可信 UI；限制方法与参数；不将桥接授予任意远端页面；校验消息来源 |
| 任意网络访问 | 链接与接口分域允许列表；重定向逐跳检查；禁止外部输入访问内网、回环和本地文件 |
| 账号串数据 | 所有私有状态按账号隔离；退出使请求代次失效；新登录不能使用旧游标与缓存 |
| 供应链风险 | 依赖版本锁定、许可证清单、漏洞与密钥扫描、源码与制品版本对应 |

Electron 的隔离与安全指导、Tauri 的能力权限模型，都强调远程内容与本地特权之间的边界；无论最终采用哪个框架，都需要落实相同的最小授权原则。[S12][S15]

### 11.2 数据与诊断

不默认上传收听历史、订阅关系、收藏内容或用户身份。诊断日志仅保留业务错误码、脱敏域名、客户端版本及必要耗时；默认本地保留最多 7 天，用户主动导出前提供内容预览。禁止包含完整手机号、Cookie、token、验证码及带签名查询参数的媒体地址。

凭据保护不可用时，默认不持久化；可由用户明确选择“仅本次会话”。不静默退化到明文文件。隐私说明需要区分“项目方不收集”与“正常播放仍会向平台/CDN 发送请求”，不能宣传完全无网络追踪。

### 11.3 本机媒体转发的条件

仅当 M0 证明必需时才增加本机媒体转发：绑定回环地址、使用随机端口和短期会话能力、限制来源、校验 Host/Origin 与所有重定向、正确透传 Range、不允许任意目标 URL、不向其他域转发账号令牌。该部分需专项安全审查，不能复用一个未鉴权的通用 API 服务。


### 11.4 使用与分发边界

官方协议涉及第三方工具、反向工程、知识产权和服务调整等限制；应据拟采用的具体接入方式评估，而不是用“开源、非商业、用户自愿”替代许可。协议页面本次显示更新日期为 2022-09-01，发布前还需重新核对适用版本。[S18]

项目使用独立图标和品牌，明确非官方关系；不打包受限内容，不移除内容方要求的标识，不绕过付费、DRM、验证码或风控。账号只读也不等于平台已授权或完全没有账号风险。[S04][S18]

这是产品风险与发布门槛建议，不是对具体接入行为合法性的最终法律结论。

## 13. 里程碑、停止条件与维护

| 阶段 | 核心交付 | 进入下一阶段的条件 |

| M0 可行性与边界 | 现有项目评估；平台接入记录；登录/刷新/个人库分页 PoC；Windows 播放/托盘/媒体键 PoC；风险评审 | G2、G3 的关键假设证实；G1 路径清楚，不把未获许可事项视为已授权 |
| M1 桌面基础 | 独立本地 UI、公开链接流程、播放器、队列、SQLite、凭据边界、安装框架 | 本地测试及故障注入通过；仅在许可边界内测试真实来源 |

### 13.1 必须停止或改范围的情况

账号访问许可或稳定性无法解决时，不继续以“完整小宇宙账号桌面端”承诺发布；可停止项目、向现有项目贡献，或经产品决策改为公共链接播放器。订阅可用但收藏不可用，也不算达成完整账号版目标。

若只能通过规避访问控制、保存明文凭据或关闭安全隔离获得功能，应停止该实现路径。若某桌面宿主无法可靠完成媒体控制，优先更换或缩减技术路线，而不是把缺陷隐含到用户体验中。

### 13.2 维护策略

平台适配层单独版本化；保存经脱敏的契约样本和兼容性矩阵；上游失效时展示具体能力状态。先允许本地关闭故障能力，后续需要远程配置时仅允许经过认证的非执行配置，不通过配置下发任意代码。

只重试幂等读取；认证、验证码及未来的写入操作不能作为普通读取自动重试。出现成规模的异常状态时发布已知问题说明，避免用户持续重复登录。公开问题单不得要求用户贴出原始 token 或完整请求头。

### 13.3 工作量与资源假设

本文件不承诺固定工期。主要成本不是页面数量，而是账号接入、Windows 原生能力、安全审查和发布后的协议维护。建议 M0 独立立项，结束后按已经证实的接口与桌面行为估算开发工作量；许可等待时间不得被当作可控开发工期。

## 14. 开源策略与最终决策清单

### 14.1 复用优先顺序

先复核 Horizon 的功能与安全实现，再选择贡献、fork 或独立重写。若现有项目已经满足核心任务，优先贡献 Windows 播放稳定性、凭据保护、完整分页及测试；不要仅为修改外观重复维护同一套不稳定接入。

Horizon 的 README 标注 GPL-3.0。直接 fork 或复制其受许可约束的实现后，不能简单将整体改标 MIT；应核对仓库实际许可证、依赖及源码交付要求。独立实现可将 MIT 作为拟议许可证，但仍须审查引入代码与依赖的兼容性。[S04][S19]

开源许可证解决代码使用授权，不自动授予平台接入、商标或播客内容权利。不要在标准开源许可证后添加“禁止商业使用”并仍宣称原许可证含义不变；平台内容限制与项目代码许可证应分开表达。

### 14.2 仓库最小交付

| 文档/机制 | 内容要求 |
| --- | --- |
| README / LICENSE | 非官方定位、实际支持平台、安装依赖、能力状态、许可证、限制与替代流程 |
| PRIVACY / SECURITY | 本地数据与凭据边界、日志范围、漏洞私密报告渠道、支持版本 |
| CONTRIBUTING | 本地开发、契约测试、实机验收、禁止提交账号凭据、版权来源说明 |
| 构建与发布 | 锁定依赖、自动测试、密钥扫描、依赖/许可证清单、可追溯源码版本与制品 |
| 兼容性记录 | 每个版本的登录、订阅、收藏、媒体播放验证日期、上游变化和已知限制 |

### 14.3 开发前应做出的决策

产品默认项已经在本文给出：Windows 11 x64、单账号、只读云端个人库、本机进度、无项目方服务器。M0 仍需对以下问题给出可核查结果，而不是模糊的“后面再研究”。

| 决策项 | 默认建议 | 证据或责任角色 |
| --- | --- | --- |
| 账号接入方式 | 优先平台允许的路径；没有依据不开放正式账号功能 | 接入记录；技术负责人 + 发布负责人 |
| 是否 fork | 先评估 Horizon，再决定 | 功能/安全差距清单；维护者 |
| 桌面宿主 | Wails 2 优先 PoC，Electron 为备选 | Windows 媒体/托盘实测；桌面研发 |
| 代码许可证 | fork 遵从适用许可；独立实现拟 MIT | 依赖与来源审查；维护者 |
| 无法读全收藏 | 阻断账号版验收，不用访客模式替代 | 多页核对记录；测试负责人 |

**建议批准的下一项工作是 M0 可行性验证，而不是直接批准“登录一定可用”的完整开发承诺。**
