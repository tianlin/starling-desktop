# Starling 0.3.0 macOS 候选版

目标系统为 macOS 14 及以上，分别提供 Apple Silicon（arm64）和 Intel（amd64）应用包。核心业务与 Windows 共用。候选包使用 ad-hoc 签名，未进行 Developer ID 签名或 Apple 公证；构建成功不代表已通过所有 Mac 实机验收。

## 安装与首次打开

下载与芯片匹配的 `Starling-0.3.0-macos-arm64.dmg` 或 `Starling-0.3.0-macos-amd64.dmg`，同时下载该构建的 `SHA256SUMS.txt`，在下载目录运行 `shasum -a 256 -c SHA256SUMS.txt`。

打开 DMG，将 `Starling.app` 拖入 Applications，然后从“应用程序”启动。未公证应用可能被 Gatekeeper 阻止；核对来源与哈希后，可在系统设置“隐私与安全性”中使用系统提供的“仍要打开”。受管理设备可能禁止此操作。不要关闭 Gatekeeper、SIP 或全局安全检查，也不要删除隔离属性来绕过组织策略。

更新前从菜单中退出 Starling，再替换应用。无需删除本机数据。没有自动更新功能。

## 日常操作

- 红色关闭按钮隐藏窗口，音频继续播放；点击 Dock 图标或菜单栏“星听 → 显示窗口”恢复。
- 菜单栏可播放/暂停。`⌘Q`、应用菜单或菜单栏“退出 Starling”会请求保存进度再退出；无响应前端最多等待六秒。
- 睡眠和唤醒时暂停；重新启动后不自动播放。全局媒体键与系统“正在播放”面板不在本版本支持范围内。
- 设置中启用账号接入后，使用小宇宙 App 扫码。凭据可选保存在本机钥匙串；访问被拒绝或保存失败时明确提示，不写明文文件。
- ad-hoc 构建更新后，钥匙串可能重新要求授权。不要选择允许所有应用访问；拒绝后可使用仅本次会话。

## 本机数据与卸载

数据库及设置位于 `~/Library/Application Support/Starling`，不加密全部收听元数据。保存的会话位于登录钥匙串，服务名为 `io.github.tianlin.starling.session`，显示标签为 `Starling saved session`；账号键由本应用数据路径派生，不是手机号。不同数据目录使用不同保存项，不启用 iCloud 钥匙串同步。

普通卸载：退出应用，将 `Starling.app` 移到废纸篓。本机数据与钥匙串保存项会保留。

彻底清理：先在应用设置中“重置全部本地数据”，确认没有清理失败提示，再退出并删除上述数据目录及应用。如果应用已经删除，使用“钥匙串访问”查找上述服务名/标签，确认属于 Starling 后删除对应项，再删除上述数据目录。删除失败不能视为凭据已清理；不承诺取证级擦除。WKWebView 可能保留系统管理的缓存，不能套用 Windows WebView2 缓存目录清理结论。

## 开发构建

需要 macOS 14+、Xcode Command Line Tools、Go 1.26.8、Node.js/npm 和 Python 3；CI 固定 Node 22.16.0。在仓库根目录运行：

```sh
bash scripts/build-macos.sh
```

脚本按本机架构构建，分别检查根模块和 `desktop/` 模块，前端测试后构建 Wails 2.11.0，验证签名、架构、系统版本和动态库，再生成 DMG、哈希、漏洞扫描及依赖材料。产物位于 `build/macos-arm64/` 或 `build/macos-amd64/`。没有从 Windows 交叉编译 Cocoa 的流程。

本次唯一 `App.Call` 绑定签名未变，候选构建跳过绑定生成。修改绑定签名时，需要在隔离的开发环境重新生成绑定并验证。

```sh
bash scripts/smoke-macos.sh build/macos-arm64/Starling-0.3.0-macos-arm64.dmg
```

启动冒烟从 DMG 复制应用，在临时 HOME 中以访客启动，检查 WebView 就绪、数据库创建及 Apple 退出事件；不会启用账号或执行平台写入。钥匙串原生测试单独创建临时钥匙串并只写合成数据。此自动化不验证实际出声、扫码结果或长期稳定性。
